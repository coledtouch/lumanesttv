# Tuner for Samsung Tizen TV

This is the Samsung TV web application in the LumaNest TV monorepo, separate from `../android` and `../webos`. It provides Home, Live TV with a guide and preview, Discover, Library (movies and series), Search, Settings and Multi View, using a directional pad, OK and Back. The application/package IDs are `TunerTv001.Tuner` / `TunerTv001`; version is 1.6.1.

The runtime uses ES5 JavaScript, local HTML/CSS and Samsung's built-in AVPlay. HTTP(S) provider requests and artwork are allowed; scripts are restricted to the packaged application and the TV's local WebAPI library. The only page the app may show in a frame is lumanest.tv's trailer player (`frame-src`/`child-src https://lumanest.tv`). No remote scripts, inline script handlers or eval are permitted. Provider accounts are entered on the device and must never be embedded in a widget or committed to source.

The first load of a new playlist downloads and prepares the provider's catalogs. Live TV, Movies and Series load independently, so each section becomes available when it finishes. Later launches restore the finished catalogs from the TV's private storage, without repeating their parsing and filtering. Fresh saved catalogs skip provider list requests for two hours for Live TV and twelve hours for Movies and Series. Older catalogs remain available while updates run in the background; guide listings load separately.

Changing the account, local ZIP or live stream format selects a separate cache. Refresh requests new provider lists while keeping the saved library available. Storage failures fall back to provider loading, with a bounded saved Live TV catalog where local storage permits it. The cache speeds up repeat launches; the first provider load still depends on the network and provider response. Cache identity metadata uses a SHA-256 digest of the account and lineup configuration.

## Prepare and check the widget

Use Node.js 18 or newer on the development PC. From the repository root, run `cd apps/tizen`, then:

```powershell
npm install --no-package-lock --ignore-scripts
npm run check
npm test
npm run build
```

The build copies only `config.xml`, `index.html`, `css/app.css`, the four runtime JavaScript files, and `assets/icon.png`. Tools, tests, node_modules, provider exports, preferences and certificates are excluded. Outputs go to the repository's ignored `output/tizen` directory (`../../output/tizen` from here). Every build creates clean staging, validates ES5 syntax, application identifiers, privileges, CSP and ZIP checksums, and produces `Tuner-1.6.1-tizen-UNSIGNED.wgt`. Pass an output folder to `node tools/build.js <output-folder>` or use the PowerShell packager's `-OutputDirectory` option to choose another location.

**The unsigned widget is a staging artifact. It cannot be installed on a physical Samsung TV.** It needs a Samsung author/distributor certificate profile containing the target TV's DUID.

For a local browser preview:

```powershell
npm run serve
```

Open `http://127.0.0.1:8181`. This preview uses HTML video when available; it does not simulate or validate Samsung AVPlay, TV codecs, device privileges or certificate installation. The server serves only runtime assets and never exposes private account or certificate files. Trailers do not play in the preview: lumanest.tv's trailer page makes its player only inside the packaged app (a `file://` page), never under a website's address such as `http://127.0.0.1:8181`, so the overlay stays black and after 12 seconds the preview shows the QR dialog instead.

## Connect the TV

Samsung's [TV device setup](https://developer.samsung.com/smarttv/develop/getting-started/using-sdk/tv-device.html) requires Developer Mode:

1. Open the TV's Apps screen and enter **12345** using the remote's number panel.
2. Turn Developer Mode on and enter the development PC's current local IPv4 address.
3. Restart the TV as the setup screen instructs. The PC and TV must share the local network.

Find the TV address in its network settings. The included read-only discovery tool checks Samsung SSDP responses and known local neighbor addresses; it does not scan a subnet, wake a TV, pair a remote, launch apps or change settings:

```powershell
.\tools\Discover-Tv.ps1
# Or supply an address you already know:
.\tools\Discover-Tv.ps1 -KnownAddress <TV-IP>
```

It reports the TV's name, model and developer-port status. A closed port 26101 means the SDK cannot connect yet. Discovery metadata alone does not prove the device supports installing this widget.

## SDK and Samsung signing

Install the official Tizen SDK Web CLI and SDB, plus Certificate Manager and Samsung Certificate Extension. The application needs no IDE, native compiler or emulator. [Samsung's CLI guide](https://developer.samsung.com/smarttv/develop/getting-started/using-sdk/command-line-interface.html) documents packaging, installing and launching a TV widget. The official [Tizen SDK installer documentation](https://github.com/Samsung/tizen-docs/blob/master/docs/sdk-tools/baseline-sdk/setup/install-sdk.md) documents command-line installation and package management. Retired Eclipse-based Tizen Studio IDE packages are unnecessary.

Windows SDK downloads are x64. Windows on ARM must run those tools through x64 emulation; this project does not claim official ARM host support. SDK tooling is kept outside app source, normally in the repository's ignored `output/tools/tizen/sdk` directory (`../../output/tools/tizen/sdk` from here). Set `TIZEN_SDK` or pass `-SdkPath` for another installation. Node-only validation and unsigned widget builds do not require this SDK.

Samsung's [certificate workflow](https://developer.samsung.com/smarttv/develop/getting-started/setting-up-sdk/creating-certificates.html) includes an interactive Samsung account sign-in. Use Samsung Certificate Extension 2.0.73 or newer; [older versions cannot create certificates after September 2025](https://developer.samsung.com/smarttv/develop/getting-started/setting-up-sdk/installing-tv-sdk.html). Create a **Samsung TV** profile, create or select an author certificate, then issue a Samsung distributor certificate with the connected TV's DUID. Permit application installation for that device if the SDK requests it. A generic Tizen certificate or a self-signed ZIP is insufficient.

Open the standalone Certificate Manager with the included launcher:

```powershell
.\tools\Open-CertificateManager.ps1
```

This standalone Eclipse-based tool requires its bundled x64 Java 8 runtime. The launcher supplies compatible JVM arguments; Java 17 fails because the tool depends on the removed `javax.annotation` classes. This runtime choice applies to the certificate tool, not the web application's TV JavaScript. A different Java 8 installation can be supplied with `-JavaPath` pointing to its `javaw.exe`.

Keep author/distributor certificates, passwords and `profiles.xml` private and out of Git. The default private folder is the repository's ignored `signing/tizen` directory (`../../signing/tizen` from here), with the Certificate Manager workspace under that same private folder. An empty checkout does not reuse certificate profiles from a previous workspace. Preserve the author certificate for future updates. The private certificate profile must reference the actual private certificate paths; do not copy a profile into the widget. Set `TUNER_TIZEN_PROFILES` or pass `-ProfilesFile` to select another profile file, and use `-WorkspacePath` with the Certificate Manager launcher to select another private workspace, including a location outside the checkout. Do not put passwords in command arguments or documentation.

After that one-time profile setup:

```powershell
.\tools\Package-Tizen.ps1 -CertificateProfile TunerTV
.\tools\Install-Tizen.ps1 -TvAddress <TV-IP> -Widget ..\..\output\tizen\Tuner-1.6.1-tizen.wgt -Launch
```

The package script builds fresh staging, invokes the official signer and checks that both widget signature files exist. Their presence does not prove validity: the Samsung CLI and the target TV perform certificate validation. The installer rejects unsigned widgets, checks the developer port, uses an explicit device serial, and only launches Tuner when `-Launch` is supplied. It does not uninstall other applications or reset TV settings.

## Remote control

Every screen follows one navigation model (the code is `apps/tizen/js/app.js`; LG gets the same code through `npm run sync`):

- **One focus.** Exactly one thing looks focused: a button or field with a white fill or ring, or, in the guide list, the highlighted programme. The active category, the selected channel cell, the active tab and a ✓ are selection markers, not focus. Arrows move to the nearest control in that direction and never wrap: Left/Right stay on their row, and when nothing lies directly below or above, Up/Down go to the next row in the same column (to its first control; entering a category or season row lands on the chosen one). Up from the top of a page reaches the tab bar.
- **Back goes up one level** and returns focus where you came from: a dialog closes to the control that opened it; full screen returns to the guide row of the channel being watched (under All Channels when it is outside the chosen category, e.g. tuned by number), the guide preview it was opened from, the Search result it was opened from, or the movie or series page; a page returns to its tab; another tab's bar returns to the start section (Home, or Live TV with **Open on: Live TV**), whose bar asks **Close Tuner?** with **Cancel** focused. In the guide: browsing ahead → back to now → categories → tabs. In Discover: posters → filters → tabs; Discover or Library opened from a See all tile on Home returns to that tile. A movie or series page returns to the poster it was opened from. Entering a page again restores its last focused control (Search, Settings, Multi View, the guide's category, row and time, the Home and Library row and poster, and Discover's filters and poster).
- **Live TV guide.** From top to bottom: tabs, the hero row (☆ Favorite and the preview), the categories, the channel list. Down on a focused category shows its channels. ← → walk the schedule programme by programme (gaps show "No information"); OK watches, or shows details for a future programme; Hold OK saves a Favorite. **Channel +/−** pages four rows (CH+ is page up), and **number keys** jump to a channel (up to four digits; OK confirms at once, Back cancels). While channels load, focus waits on the categories and moves to the list when they arrive; if loading fails, it moves to **Refresh playlist**. After loading or a Refresh, the guide opens on the channel being watched (or last watched), whichever tab was open meanwhile.
- **Full screen.** OK shows the controls bar with a button focused; Back hides it, then leaves. Up/Down and **Channel +/−** change channel in every state (CH+ and Down go to the next higher channel within the guide list, or all channels when opened from Search); rapid or held presses move the banner and tune 0.5 s after the last press, and OK tunes at once. In a one-channel list they only show the banner. Number keys tune a channel; the number already playing does not restart it. Movies and episodes: ← → seek 10 seconds, Rewind/Fast forward seek 30 seconds, Up in the bar focuses the seek bar, Stop leaves. A failed stream shows the bar with **↻ Retry** focused. The Guide key returns to the guide on the channel being watched.
- **Home and Library.** Poster rows; the focused row is on top with the next one below it and the focused title described above them. Left/Right move along a row; Up/Down move to the poster in the same screen column of the next row (Up from the first row reaches the tabs); **Channel +/−** move two rows. OK opens the movie or series page, the last tile (**See all**) opens Discover on that row's type and list, and **Hold OK** adds a title to the Library or removes it. A ✓ badge marks Library titles and a bar shows progress.
- **Discover.** Three filters (**Type**, **List**, **Genre**) above a poster grid. OK on a filter opens a list chooser on the current choice; choosing returns focus to the filter. The grid moves by poster without wrapping, Up from its first row reaches the last focused filter, Down from a column past a short last row lands on its last poster, and **Channel +/−** page two rows. More titles are computed as the grid scrolls.
- **Text fields** (Search, Settings, the Multi View channel search) are read-only until OK, so arrows and Back always work on them; OK opens the TV keyboard (yellow ring). Done or Enter moves on, Back or Cancel closes the keyboard, Up/Down close it and move. Typing a character on a focused field also starts editing. A field that is not being edited passes the Guide, Channel +/−, media and color keys on. Unsaved Settings typing survives leaving the page.
- **Dialogs.** Lists (subtitles, audio, the Multi View channel list, Discover's filters) move with Up/Down and open on the current choice; button rows move with Left/Right. CH+/− page eight channels in the Multi View list.
- **Hints** on screen (top-left label, guide footer, player hint) are computed from the state the next key acts on.

The on-screen keyboard behaviour (a read-only field keeps the Samsung IME closed; refocusing an editable field opens it; IME Done 65376 and Cancel 65385) still needs confirmation on a physical TV.

## Movies and series

Movies and series follow the shared design in [`docs/browse.md`](../../docs/browse.md). **Home** shows Continue watching (5 titles or more), Popular, Featured, one Movies/Series pair per streaming service, Recently added and Top rated; a row appears with at least 5 playable titles and shows up to 20. **Discover** filters by Type (Movies, Series), List (Popular, Featured, Top rated, Recently added, A–Z, each service) and Genre. **Library** shows Continue watching, Favorite movies, Favorite series and Recently watched; favorites share the existing Favorites store (a movie or series id next to channel ids), progress comes from the saved playback positions, and an episode remembers its series so a series continues on the episode in progress, or the next one after an episode is finished. Movie and series pages open from any poster and keep Resume and the season and episode list.

Only the customer's own catalogue is shown. Popularity comes from `https://lumanest.tv/api/catalog/rows?v=1` (public, no login): the app keeps the answer for 12 hours in local storage and keeps using an older copy while a refresh fails; HTTP 503 and unreadable answers are never stored, and `source: "none"` (no TMDB on the server) is stored and handled as the fallback. Titles match TMDB on the provider's `tmdb`, `tmdb_id`, `info.tmdb_id` or `info.tmdb` (a string of 1 to 12 ASCII digits, or a whole number; arrays and other values are no id), otherwise on the normalized title and a year within one, following `docs/browse.md` (`tests/browse.test.cjs` runs every case in `docs/browse-cases.json` with and without `String.prototype.normalize` and with the oldest TV browsers' `\s`, which also takes U+180E, and times a name ending in 40 quality tags and one with 16,000 spaces inside, as it does M3U names, before an episode marker or not, and category names; `tests/data.test.cjs` times live channel names with long runs of spaces). Provider fields lose only tab, line feed, vertical tab, form feed, carriage return, space and the Unicode spaces of `docs/browse.md` at their ends, with a loop over the character codes rather than a pattern. Without TMDB data, Popular and Featured are hidden, service rows come from category names (Netflix, Disney, HBO/Max, Prime/Amazon, Apple, Hulu, Paramount, Peacock), Recently added uses `added` (movies) or `last_modified` (series) and Top rated the provider rating. When TMDB data is in use, Settings → About shows the TMDB notice.

Settings → **Movies & Series: USA only / All** (separate from **Channels: USA only**) defaults to USA only: a title matched to TMDB needs `US` among its countries of origin (an origin without a two-letter country, such as `[]` or `["USA"]`, counts as unknown) and a category without a non-US country or language tag; an unmatched title needs the category check only. This also keeps out US titles filed in foreign-language categories, usually dubbed copies. Search applies it to movies and series too (channels follow **Channels: USA only** as before). Library and Continue watching show the customer's own titles regardless of this switch. Copies of one movie under the same name fold into one title that plays the copy in a category the filter keeps, ahead of a newer copy under a foreign tag.

Movie and series pages also look up the title's trailer at `https://lumanest.tv/api/extras/trailer` ([`docs/extras.md`](../../docs/extras.md); the TMDB key stays on the server), once per title per session. **Trailer** appears after **Add to Library** only when a trailer was found, in place and without moving focus. Since 1.6.1 the trailer plays inside Tuner: a full-screen overlay over the details page shows `https://lumanest.tv/embed/trailer?v=1&k=<key>` in an iframe (YouTube refuses embeds from a packaged app, so the YouTube player runs in that page on lumanest.tv). The remote's keys stay in the app document: OK and Play/Pause toggle (until the trailer has played they send Play), Play, Pause, Left/Right and Rewind/FastForward seek 10 seconds, Stop and Back close the overlay, and focus returns to **Trailer**; the app and the page talk with `postMessage` (JSON strings; the app accepts messages only from `https://lumanest.tv` and from its own frame), and the pure rules (frame URL, message checks, keys, commands) are in `js/data.js` (`TunerData.extras`). A player error, no "ready" from the page within 12 seconds or a frame that cannot load closes the overlay and opens the YouTube app instead, with `tizen.application.launchAppControl` (operation `http://tizen.org/appcontrol/operation/view`, `PAYLOAD` `{"values":"v=<key>"}`), trying the app ids `111299001912` and then `9Ur5IzDKqV.TizenYouTube`; this needs the `application.launch` privilege in `config.xml`. When neither opens, the TV shows "Watch the trailer on your phone" with the QR code lumanest.tv sends (drawn by `js/pairing.js`) and the `youtu.be` link. `config.xml` allows framing lumanest.tv in its CSP and lists `<tizen:allow-navigation>lumanest.tv www.youtube-nocookie.com www.youtube.com</tizen:allow-navigation>`: with a CSP, Tizen's runtime blocks any http(s) navigation outside that list, frames included, and opens the blocked address in the browser instead; a listed host may also open a window over Tuner, so only the player page and the YouTube player's hosts are listed, with no wildcards. The overlay's iframe is sandboxed (`allow-scripts allow-same-origin allow-presentation`): the player inside cannot open windows (its "Watch on YouTube" and end-screen links) or navigate Tuner. `tools/widget.js` accepts exactly these values. If a TV opens the browser on another address while a trailer plays, add that exact host. Check on a TV before a release that the trailer plays with sound and that Back closes it; `TRAILER_IN_APP` in `js/app.js` set to `false` sends Trailer straight to the YouTube app. Because the app embeds YouTube's player (YouTube API Services), Settings → **About Tuner** shows the privacy policy address (`tunertv.app/privacy`) and, while `TRAILER_IN_APP` is `true`, the YouTube Terms of Service address (`www.youtube.com/t/terms`). Samsung does not document the YouTube payload: if YouTube opens on its home page instead, set `YOUTUBE_LAUNCH` to `false` and the fallback is the QR dialog.

Settings → **Open on: Home / Live TV** picks the start section. It is decided once when this version first runs: **Live TV** when a playlist is saved and the library records a watched channel (the last watched channel or Most Watched), **Home** otherwise, including new installs; after that it only changes in Settings.

Each catalogue is indexed once per load (`js/data.js`, `createIndexBuilder` / `createMatcher`). Catalogues up to 3,000 titles are indexed at once; larger ones in slices of about 30 ms between key presses, while the page shows "Preparing your movies and series" and focus waits on the section's tab (it moves to the rows when they appear, unless a key was pressed meanwhile). A catalogue delivered again (the saved copy and then the provider's, or Refresh) and new rows are indexed or matched the same way while the previous index stays on screen with its focus; locking adult content again drops it at once. Only the focused shelf row and the one below it, or three grid rows, are in the DOM, and posters load when they come into view.

## Playback and port limits

AVPlay handles supported HTTP(S) live/VOD streams, seeking, available audio/subtitle tracks and fallback stream candidates. All audio languages remain available. Container/codec support, adaptive streaming, network behavior and track controls depend on the TV model, firmware and provider; successful desktop playback cannot establish TV compatibility. [Samsung's AVPlay guide](https://developer.samsung.com/smarttv/develop/guides/multimedia/media-playback/using-avplay.html) describes the native player lifecycle and supported features.

Subtitles work the same way for live channels, movies and episodes. While watching, the yellow key, the remote's CC/Caption key (registered when the TV supports it) or the **CC Subtitles** player button opens a chooser with Off and every text track AVPlay reports (`getTotalTrackInfo` type `TEXT`). The choice uses `setSelectTrack('TEXT', index)` and `setSilentSubtitle`; AVPlay delivers cue text through `onsubtitlechange`, which Tuner draws at the bottom centre on a dark background. A stream without text tracks shows "No subtitles in this stream". Settings → **Subtitles: Off/On** controls the default: when On, each new stream selects an English track, or the first one, as soon as the TV reports it. Closed captions embedded in the broadcast video (CEA-608/708) are listed only when the TV's AVPlay exposes them as a `TEXT` track; most Samsung firmware does not, and then the TV's own Accessibility caption setting is the way to show them.

Movies and episodes also get English subtitles from OpenSubtitles.com through lumanest.tv ([`docs/extras.md`](../../docs/extras.md)): when one starts, the app asks `https://lumanest.tv/api/extras/subtitles` with the title's TMDB id (an episode: the series' id with its season and episode numbers), or its name and year when it has none; live channels never ask. Answers are kept for the session. The chooser lists Off, the stream's tracks, then up to three OpenSubtitles tracks with the line "Subtitles provided by OpenSubtitles.com" (also in Settings → About). A file is downloaded only when its track is shown (chosen, or picked automatically) and kept in memory for the last few titles. With **Subtitles: On**, the automatic choice is an English stream track, else the first OpenSubtitles track, else the stream's first track. Tuner draws OpenSubtitles cues itself in the subtitle layer as plain text (`textContent`), reading AVPlay's position five times a second and at once after a seek, while the stream's own subtitles stay silent; a chosen track that cannot be loaded leaves subtitles off with a short message. When the server has no OpenSubtitles key (`not_configured`), or any request fails, nothing extra is listed and nothing is shown.

The provider's own live category "Most watched now" (and "Most watched", with a leading or trailing US, USA or EN tag) is hidden by its name on every line, in both channel lineups; channels listed only there are dropped, as they are copies of channels in other categories. Tuner's own **Most Watched** is unaffected.

Adult categories are hidden by default across Live TV, Home, Discover, Library, the guide, Search, Favorites, Most Watched and Continue watching. A category is adult when the provider marks it or its streams `is_adult`, or its name contains a standalone XXX, Adult(s), 18+ or Porn (Adult Swim is not adult). Settings → **Adult content: Locked/Unlocked** unlocks them with a 4-digit passcode, created on first use by entering it twice; locking needs no passcode, and the lock returns when Tuner restarts. **Change passcode** asks for the current one. Five wrong entries impose a 60-second wait. The passcode is entered with the remote's number keys or an on-screen digit pad; only a random salt and an iterated, salted SHA-256 digest are stored locally. A forgotten passcode is reset by reinstalling the app or clearing its data.

The full-screen player always uses the whole 1920x1080 stage (`setDisplayRect(0, 0, 1920, 1080)`), reapplied after preparation, resume, buffering and channel changes, so the guide preview's rectangle cannot remain. Back in the guide, the picture returns to the preview frame. The display method is letterbox, set once per stream before preparation and never changed during playback: some Samsung TVs keep a full-screen display mode covering the whole panel after the rectangle shrinks, and a full-stage letterbox already fills the screen for 16:9 video. Playback controls hide five seconds after the last remote key; they stay while a dialog is open or playback is paused or failed.

Multiview targets **two live channels**, respecting a two-stream provider limit. On supported Tizen 7.0+ devices it uses two native AVPlayStore managers in Samsung's in-app MAIN/SUB multiview mode, with one audible channel. Ordinary single-channel playback remains available when a Samsung device cannot allocate dual players; the app reports the limitation. The browser preview uses two HTML video surfaces for UI checks, which does not verify native dual playback or the M7's decoder resources. A PC bridge is not required by this port. See the [AVPlayStore API](https://developer.samsung.com/smarttv/develop/api-references/samsung-product-api-references/avplaystore-api.html) for model-dependent native player support.

Active Multi View fills the viewport and hides the app header and setup dashboard. The main Picture in Picture feed covers the full screen; side-by-side feeds use the full width and preserve their picture proportions. Compact controls and channel labels hide after five seconds. OK, arrows or Menu reveals them without changing either stream. PiP borders hide with the controls, and unavailable slots leave no empty box over the main video. Back hides visible controls first; pressing Back while they are hidden stops both channels and returns to the Multi View setup screen with both channels still chosen and **Watch both** focused. Back again reaches the tab bar. Choosing a different layout resizes the same native players without reconnecting.

Native playback also checks for streams that silently stop advancing while AVPlay still reports Playing. After roughly 30 to 35 seconds without progress, only the stalled stream reconnects once, then tries its available backups if another stall occurs. The healthy channel and selected soundtrack are preserved. Recovery uses the same native decoder and closes its old connection first. Paused playback, seeking, background suspension and muted streams whose native clocks still advance do not trigger this recovery.

Audio switches retain both connections when the TV supports changing the active route. If native routing fails, Tuner uses the main picture's default audio instead. Make main promotes the chosen channel to the main picture and restarts both streams: both old connections close before either reopens, and the same two native managers are reused. This TV fallback briefly reloads the pictures when changing the audible channel. Native routing errors are never accepted as success based only on an audio flag. A failed channel remains unavailable for audio selection; recovery to the healthy channel follows the same safe audio path.

The Android embedded jlibtorrent engine is not part of this web widget. Raw magnets, peer-to-peer torrent downloading and Android Picture-in-Picture are unavailable. A direct HTTP(S) stream from a provider or a compatible debrid service is required; the Android Streaming/Torrentio discovery interface is not included in this initial Tizen port. Native DRM systems require an authorized license flow and device support; this widget does not bypass DRM or provide license integration. The guide preview is an in-app player surface, not system Picture-in-Picture.

Samsung runtime storage and network policies differ from Android. Accounts, Favorites and resume points are stored locally by this port; they are not automatically copied from the Android app. Browser tests verify UI/data logic and mocked player behavior, while a signed physical-TV test is still required for installation, playback and remote responsiveness.
