# Tuner by LumaNest TV: notes for coding agents

IPTV player for Android TV / Google TV. Kotlin, Jetpack Compose (no tv-material), Media3 ExoPlayer, OkHttp, Coil 2. Single activity, no DI, no Room.

## Build and test (PowerShell, from this folder)

Use JDK 17 and Android SDK platform 37. Set `JAVA_HOME` and `ANDROID_HOME`, or keep the SDK path in ignored `local.properties`. The checked-in wrapper uses Gradle 9.8.1.

    .\gradlew.bat assembleRelease        # app\build\outputs\apk\release\app-release.apk (release-key signed when the external key is available)
    .\gradlew.bat testDebugUnitTest      # parsers, name matching, Robolectric screenshots -> app\build\screens
    .\gradlew.bat bundleRelease -Pstore=true    # store edition for Google Play -> app\build\outputs\bundle\release\app-store-release.aab
    .\gradlew.bat assembleRelease -Pstore=true  # store edition for Amazon -> app\build\outputs\apk\release\app-store-release.apk

Signing configuration is private. `-PtunerSigningProperties` takes precedence over `TUNER_SIGNING_DIR`, followed by the ignored repository-root `signing/android/keystore.properties`. Without the existing release key, release builds remain unsigned. Never create a replacement release key or commit signing properties, certificates, or SDK paths.

Install on a test TV after its owner pairs wireless debugging:

    & "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" connect <TV-IP>:<DEBUG-PORT>
    & "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" install -r app\build\outputs\apk\release\app-release.apk

The connect port changes if wireless debugging is toggled; `adb mdns services` lists the current one.

## Layout (app/src/main/java/tv/lumanest/tuner)

- `data/Repo.kt`: single source of truth. Loads the active source, holds StateFlows for channels, VOD, series, trending; guide data keyed by Channel.key; logo fallback index.
- `data/Xtream.kt`: player_api.php client and streaming JSON parsers. Providers repeat items once per category, so parsers merge by id into `categoryIds`. Prefers `direct_source` URLs.
- `data/M3u.kt`, `data/Xmltv.kt`: streaming parsers. XMLTV keeps only wanted channels inside a time window. M3U names and groups follow docs/browse.md "M3U playlists" like every other app: one pass over each `#EXTINF` line (`M3u.readExtinf`: `"..."` and `'...'` values, the first comma outside them, a key's first value), tags matched ignoring ASCII letter case only, and `Channel N` counting every entry, movies too.
- `data/ChannelMatch.kt`: fuzzy name keys ("US: CNN HD" == "CNN") for guide and logo matching.
- `data/FreeEpg.kt`: epgshare01 regional guides used to fill channels the provider guide misses.
- `data/PhoneSetup.kt`: tiny LAN web form (port 8686) served while the add-playlist screen is open.
- `player/PlayerHolder.kt`: one shared ExoPlayer; guide preview and full screen reuse it.
- `ui/Guide.kt`: cable-style grid. One focusable grid with custom D-pad handling (not per-cell focus) for speed with 17k channels. Key handling reads state, not the last composition.
- `data/BrowseCatalog.kt`, `data/CatalogRows.kt`, `data/CatalogRowsClient.kt`: Movies & Series browsing (docs/browse.md) in plain Kotlin. The popularity lists from lumanest.tv (12 h disk cache, stale copy on failure), TMDB matching, the "Movies & Series: USA only" rule, genres and every Home/Discover list, indexed off the main thread for `Repo.browse` by `BrowseBuilder`, which reuses the movie or series index whose inputs did not change. `Movie.aliases` (older uploads folded in by `Cleanup.movies`) keep Library keys and saved positions working after a re-upload. The category filter, title normalization and years use the shared patterns in docs/browse.md; `BrowseCasesTest` runs every case in the repository's `docs/browse-cases.json` (shared with the other apps, never copied; the `m3u` cases through `M3u.parse`), except the `tmdb` cases, which `ParserTest` runs under Robolectric through Android's `JsonReader` and `Xtream.tmdbOf`.
- `ui/Browse.kt` (Home and Library poster rows), `ui/Discover.kt` (filters and grid), `ui/Details.kt` (detail pages, Add to Library). `ui/Player.kt`: live + VOD player.
- `data/Extras.kt`, `player/SubtitleChoice.kt`, `ui/Trailer.kt`, `data/HiddenLiveCategory.kt`: docs/extras.md. `ExtrasClient` asks lumanest.tv `/api/extras/subtitles` and `/api/extras/trailer` (never OpenSubtitles or TMDB; answers kept for the session, 200 at most; off in Robolectric unless a test sets `Extras.client`). `SubtitleFiles` keeps downloaded WebVTT files in `cacheDir/subtitles` (20 files, 7 days). `PlayerHolder` attaches only the OpenSubtitles track being shown, as a `file:` subtitle, read through `PlayerDataSource`: http(s) goes to `LiveSlotDataSource`, `file:` only inside `SubtitleFiles.dir` (canonical path), and every other link (other files, content:, asset:, data:, udp:...) fails as an unsupported scheme, so playlists and manifests can't open local files (never use Media3's `DefaultDataSource` there). With Subtitles On it waits at most 1.5 s for it at start, reloads at the position for a later or picked track, and enforces the automatic order (stream English, provider English, OpenSubtitles, then the old fallback) in `chooseText`. Side-loaded tracks carry format ids `provider:<n>` and `opensubtitles:<id>`. The Trailer button follows Add to Library and plays the trailer in Tuner (`ui/TrailerPlayer.kt`): a full-screen dialog with a WebView showing `TrailerPage.html(key)` (YouTube's IFrame API; the checked key is the page's only variable part), loaded with `loadDataWithBaseURL("https://" + BuildConfig.APPLICATION_ID + "/", ...)` because YouTube refuses embeds without an origin (errors 152 and 153) and its Required Minimum Functionality asks a WebView app to name itself by its app id, laid out at the screen's own width (`TrailerPage.VIEWPORT`, `width=device-width`; no `useWideViewPort` or `loadWithOverviewMode`: 1.8.1's 1920-pixel layout made YouTube see a 4K player at density 2 and pick 4K, a black screen on an onn 4K Pro), and loaded only once the WebView is attached to its window (`OnAttachStateChangeListener`, then a post; never twice). The page and the app talk only over a `WebMessagePort` posted to that origin at `onPageFinished` (events `ready`, `state:<n>`, `error:<n>`; commands `toggle`, `play`, `pause`, `back`, `forward`; and the page's `diag:` diagnostics, which `TrailerEvent.parse` ignores: they are logged, and a snapshot's state and time become `TrailerEvent.Progress` for the stall check), never a `@JavascriptInterface`; the page appends YouTube's API script only in its `load` listener, or the load event (and the port) would wait for YouTube's whole embed. The WebView is made after the player's first frame and stays composed under Tuner's "Loading trailer" (the name and the remote's keys), which is drawn over it while the page loads, until YouTube's player is ready (`TrailerPolicy.showsLoading`), so a cold web engine never shows as a black screen; from then on nothing of Tuner's is drawn over YouTube's player (its Required Minimum Functionality's "Overlays and frames"). The page doesn't autoplay (`autoplay:0`, no `playVideo` at ready): once a frame without "Loading trailer" has been drawn the app sends `play` (`TrailerPolicy.startsOnceShown`; never while the app is paused or after a viewer command), since the Required Minimum Functionality ("Autoplay and scripted playbacks") forbids starting a playback before more than half of the player is visible. The page itself also shows "Loading trailer" and the keys under the player's element. It loads any https request or frame (never block YouTube's player or its ads: YouTube API policies; WebView never asks `shouldOverrideUrlLoading` about an http(s) frame, only about the page's own navigations and frames going to other schemes, so `TrailerPage.HOSTS` limits nothing in practice), never navigates its page (every navigation WebView asks about is refused): a main-frame YouTube link (logo, title or channel, with a mouse; `TrailerPage.opensInYouTube`) goes to `TrailerLauncher.openLink`, the YouTube packages only and never an intent without a package (no browser, store edition included), and closes the player (`TrailerEvent.Left`); other links open nothing; Android 6's deprecated overload can't tell the page from a frame and refuses everything (its YouTube links open nothing), keeps third-party cookies off and is destroyed when the player closes, the activity stops or the page leaves (its storage, cookies and HTTP cache are cleared). OK and Play/Pause toggle, Left/Right seek 10 s, Back or Stop close and the focus returns to Trailer; the trailer's end closes it. Any player error but 100, no Ready within 12 s, a ready player that hasn't said playing within 10 s of ready or of the viewer's last command (`TrailerPolicy.onPlayingTimer`; not while the viewer's command left it paused or the app holds it paused), a playing trailer whose time stands still for 10 s in the page's snapshots (`TrailerStall`; a time of 0 never counts, YouTube may show an ad first), or no WebView (`TrailerPolicy`): the YouTube apps in `TrailerLauncher.PACKAGES`, then a QR dialog; error 100 (video removed or private) closes with a toast instead. Tests swap the WebView for a stand-in through `LocalTrailerSurfaces`. `TrailerLog` logs every step under the tag `TunerTrailer` (`adb logcat -s TunerTrailer:V chromium:V`): device, WebView and screen, attach, size, load, page and HTTP errors by host, blocked requests by scheme and host, every page message (snapshots included), console messages (level, host and line, 300 characters, queries cut), the port, pauses, the renderer, and each decision and timer; never the playlist, lines, stream addresses or any address's query, and `setWebContentsDebuggingEnabled` stays off. Cards on Home, Library, Discover and Search start their title's trailer lookup after 400 ms of focus or on OK (`Extras.prefetch`, `TrailerPrefetcher`: at most 2 at once; focus-started lookups at most 6 uncached a minute, a lookup by name counting two, so lumanest.tv's 12 a minute per client is never used up by browsing; OK is never held back), `ExtrasClient` shares a lookup already on its way, and details pages read the session's answer while composing (`rememberTrailer`), so the button is there on the first frame; `trailerQueryOf` builds the same lookup for a card and its page. `HiddenLiveCategory` hides the provider's "Most watched now" (a loop, no regex) in `Repo.liveCatalogue` and on restored live snapshots, never in the trending playlist; `ExtrasCasesTest` runs the `live_category` cases of the repository's `docs/extras-cases.json`.
- `ui/TvTextField.kt`: opens a native AlertDialog EditText. Compose text fields were unreliable with the Google TV remote keyboard.
- `ui/Common.kt`: `Palette` (theme-aware, snapshot state), `Themes`, `FocusBox` (the standard D-pad target).

## Gotchas

- On devices `java.util.regex` is ICU, so `\s` and case-insensitive matching follow Unicode there but not in the JVM unit tests. The Movies & Series rules replace the Unicode spaces first (`BrowseText.spaces`) and ignore case by matching lower-case patterns against an ASCII-lower-cased copy (`BrowseText.asciiLower`), never with `IGNORE_CASE` (docs/browse.md, "Spaces and letter case"). Provider fields and names are trimmed with `BrowseText.trimField` and `BrowseText.trimEnds`, never Kotlin's `trim()` or `isBlank()`, which also take U+001C to U+001F (docs/browse.md, "Trimming").
- `readAny` gives a JSON number as a `JsonNumber` (its text), not a `String`, so a provider TMDB id can tell `1e3` (an id) from `"1e3"` (none). Read fields with `str()` or `textOf()`, which accept both, rather than `as? String`.
- Every Lazy list key must be unique. Duplicate provider ids crashed Movies in 1.0.1; keep merging in the parsers.
- Clickable is only focusable in keyboard input mode. Tests force `InputMode.Keyboard` to match a TV.
- Example provider: Xtream API at https://mybunny.tv, streams served from turbobunny.net (about 17k live, 17.6k movies, 3.8k series).
- No em dashes in user-facing text or docs.
- targetSdk stays 35. Google Play asks TV-only apps (the store edition) for API 34 only, and targeting 36 would let Android 16 ignore `screenOrientation="landscape"` for the lumanest.tv APK on tablets and Chromebooks. Robolectric 4.14 also stops at API 35.
- The store edition never names a streaming service (Netflix, Disney+, Max, Prime Video, Apple TV+, Hulu, Paramount+, Peacock) in Home rows or Discover lists: `StreamingServices.shown(store)`.
- Two editions, one codebase: `Edition.STORE` (`-Pstore=true`) is the Google Play / Amazon build. Keep the direct (lumanest.tv) edition's behaviour unchanged when adding store-only rules; screens and `Prefs` take a `store`/`storeBuild` parameter defaulting to `Edition.STORE`, and `Repo.storeEdition` switches the library rules, so tests cover both (`StoreEditionTest`, `StoreEditionScreensTest`, `StoreEditionLibraryTest`). CI also runs those three classes with `-Pstore=true`, so they must pass explicit edition values (the manifest test reads `Edition.STORE` on purpose); other tests assume the direct edition.
